# 0.1.17：Gemini 長章節串流大小修正

2026-10-29。使用者提供的 Rawkuma《Isekai Kenkokuki》第 1 話，Chrome 現場顯示 19/19 張已呈現、二段校正失敗，原有譯文保留；錯誤為 `GeminiFailure: Gemini 回覆超過大小限制`。現場唯讀截圖及可見狀態保存在本機 `artifacts/gemini-size-limit/live-before.*`，未重送原請求。

錯誤文字直接來自 `src/gemini-web.ts` 的本機判斷：將所有串流片段累加到一個字串，超過 2,000,000 個 JavaScript 字元即中止。這個數值限制的是整條原始串流，並非最終譯文字數或 Gemini 的模型 token 上限。

Gemini 協定的後續片段可包含逐漸增長的答案快照。相同答案內容因而可能傳輸多次，短得多的最終文字仍可使整條串流超過舊界限。以 19 頁、228 框、320 個累積快照的原創 fixture，已在修改前重現同一句錯誤（`reproduction.log`），修改後的單元回歸通過。原次真實請求的完整網路串流未被保存，無法補算該次實際傳輸量及片段數；累積快照案例是可重現的機制驗證。

修正後逐行解析 RPC frame，只保留尚未完成的單段、最新候選答案及最多 24,000 字元原始診斷摘錄。UTF-8 可跨網路 chunk 邊界，最後一段可無換行。每段仍限制 16,777,216 個 JavaScript 字元，候選答案限制 2,000,000 字元；180 秒等待上限與完整 JSON／區域 ID 驗證維持。整章輸入仍為最多 60 頁、800 區域及 120 KB，沒有將章節拆成互不相干的翻譯。

診斷新增實際接收位元組、接收字元、候選段數、最大單段、最新答案字元及摘錄字元數。設定中的匿名協定診斷會顯示傳輸量、段數及答案大小。成功紀錄正確標示摘錄被截短，避免把 24,000 字元摘錄誤認為完整串流。

若讀取中途被大小限制或格式錯誤中止，請求狀態為結果未知，取消串流並保留鎖定，原 OCR 與譯文保留，禁止自動重送或對部分答案進行格式修補。舊版將本機大小錯誤覆寫成協定受阻的環境，只有已保留 30/30 驗證進度時才沿用成功證據；HTTP 403／429、缺少證據與其他協定錯誤仍受阻。

npm run audit:package

測試結果、建置及套件收據保存在本機 `artifacts/gemini-size-limit/`。隔離擴充功能測試使用原創文字與模擬 Gemini 回覆，分開列報；使用者 Chrome 重載修正版後的真實章節驗收另行記錄。

本機測試 152 項通過，型別檢查零錯誤／警告，建置及離線權重白名單通過。Chrome for Testing 與 Edge 的實際 background → offscreen → 串流解析 → storage 路徑均通過：19 頁／228 框的二段校正與直譯，各接收 9,571,188 bytes、4,600,414 字元、320 段；最後答案 23,122 字元，原始摘錄 24,000 字元，所有區域 ID 對應完成。

兩瀏覽器也通過未關閉串流的答案超限測試：中止 reader、保存結果未知鎖定，再次相同請求於提交前受阻；兩次成功及一次超限合計僅三個模擬 POST，既有初譯維持。早期測試器的 profile 名稱白名單、折疊診斷區尚未開啟及已關閉串流的取消計數問題均已定位，原失敗收據保留；它們與產品回歸結果分開。

使用者確認重載 0.1.17、刷新及啟用後，由指定 Terra 6.1／medium 子智慧體在原 Chrome 分頁點擊一次「翻譯本頁漫畫」。現場從已保存的初譯重新呈現 19 頁，完成該次整章二段校正，工具列顯示 **19/19 張、147 個區域、修改 139 處**，校正後繁中可見，沒有再次提交。截圖、狀態及操作時間保存在本機 `live-after.json`、`live-after.png`、`live-after.md`。這是原失敗章節的真實流程修復證據；修改數不是人工品質分數。原次與此次真實串流大小未直接取得，與隔離測試的位元組計數分開。
