# 0.1.11：浮球與整章二段校正

日期：2026-10-15。

## 浮球事件

0.1.10 的拖曳程式在外層容器監聽 pointerdown，使用 event.target 設定 pointer capture。正式工具列位於 Shadow DOM，事件到達外層時目標已重定向為 host；後續 click 因此到不了浮球按鈕。先前測試將元件直接放在普通 DOM，沒有涵蓋這條邊界。

0.1.11 從 composedPath 取得真正帶有拖曳標記的按鈕，再設定 capture。隔離 fixture 改成 Shadow DOM，Chrome 實測收合、展開、拖曳後展開與工具按鈕；400×720 視窗的工具列仍位於可視範圍。實際擴充套件亦已確認浮球收合／展開正常。工具列改為依內容縮合，寬度上限 620px，桌面五個操作鈕同排時約 539px；窄視窗與長訊息可換行。

收合前記錄按鈕中心，元件改變尺寸後以該點對齊浮球；展開亦維持操作點。Chrome fixture 量測收合前中心 (1879, 781.5)，浮球中心 (1879, 782)，誤差為 0／0.5px；接近視窗邊界時仍以可達性限制優先。

## 校正資料流

第一階段維持 Google 網頁初譯，每張完成即呈現。全部圖片完成後，第二階段收集整章各頁的原文、Google 初譯、目前譯文及人名術語，一次交給匿名 Gemini 校訂。它能在同一請求中使用前後頁文字；圖片、人物外觀及對白指向仍留在本機，OCR 誤字也會限制品質。

頁面順序、圖片雜湊及區域 ID 組成對應，輸出要求完整 JSON 陣列。原文待覆核或沒有初譯的項目只提供背景，不交給模型猜補。回覆完整核對後才重排，遠端回覆只能改譯文，幾何位置、遮罩、排版與原文保持本機資料。數量、ID、文字與設定變更都會阻止舊結果套用。

每框保留首次初譯，後續校訂不覆寫該基準。校正結果與輸出指紋存入原有頁面快取；文字及術語未變動時可沿用，人工修改後重新計算。校正前後重新讀取快取以偵測修改競爭。最多 60 頁、800 個可校正區域、120 KB 輸入；超過上限明確停止，不偷偷拆成缺少全章上下文的獨立請求。

正常校正使用一個整章請求。已完成但格式不符的回覆最多追加一次格式修正；提交後結果未知禁止自動重送。Google 初譯保留，遠端失敗不改動現有譯圖；若在逐張重排期間取消，已完成校正版與其餘初譯會同時保留。

## 驗證範圍

30 批原創短句屬於 0.1.10 的匿名連線與格式診斷，並非 30 頁漫畫，也沒有建立整章品質分數。0.1.11 的單元測試另以 17 頁、重複區域 ID、亂序回覆核對全章一次輸入與逐框回填，涵蓋格式修正上限、保留初譯、過期回覆、人工修訂及術語變動。

第一輪 Chrome 實測完成 17/17 張 Google 初譯，第二階段於權限檢查停止：content script 沒有 chrome.permissions。修正後由背景提供狀態，對應測試確認查詢不建立推論資源。該次停止發生於提交 Gemini 之前，初譯已保存。

修正後的 Chrome 實測完成整章初譯、匿名 Gemini 全章回覆與 17 張重排，工具列回報「整章二段校正完成：128 個區域，修改 92 處」。這是一次真實網站、真實擴充套件的整章執行；初譯使用既有快取與 Google 流程，並非全新下載或獨立速度比較。全部區域通過 ID 格式核對，才開始套回原頁。修改數表示字串有變動，不代表 92 處都改善；本輪尚未完成逐句盲評與人名一致性評分。

91 個測試涵蓋格式核對、章節競爭、初譯保存、術語快取失效與背景權限狀態。最終 UI 收尾另調整操作鈕同排及收合定位；整章實測使用該次 UI 收尾前的 0.1.11 候選，翻譯與回填流程相同。

原始漫畫、逐框文字、協定資料與截圖只保存在忽略版控的本機 artifacts。公開文件僅列聚合觀察，不將 ID 完整性、短句協定測試或一章的樣本觀察提升為正式翻譯品質驗收。
