# 0.1.10 研究與量測

日期：2026-10-15。硬體為 i5-12400、約 16 GB RAM、Intel UHD 730；OCR 比較使用 CPU。正式辨識品質與漫畫翻譯可讀性須另以人工真值評分。

## 匿名 Gemini

擴充套件以 `credentials: omit` 直接請求 Gemini 網站，從匿名頁取得協定版本，再送出文字與 JSON 格式要求。所有解析程式隨套件打包；Google 帳號 cookies、認證標頭及模型等級覆寫均未接入。

初始化曾停在 0/30 批。讀取同機匿名公開頁後確認，頁面 HTTP 200，版本名稱已改為 `boq_gemini-web-uiserver_20261013.29_p0`；原解析器僅辨識舊的 `boq_assistant-bard-web-server` 名稱。補上新標籤後，擴充套件設定頁的使用者實測回報 **30/30 批通過**。這項紀錄來自實際擴充套件，初始化頁的命令列診斷則只用於定位格式變更。

每批使用兩個原創日文短句與獨立區域 ID。驗證器要求 ID 集合完全一致、無空譯文、無重複或額外 ID，通過後才開放實驗來源；30 批共核對 60 個區域的識別碼與格式；譯文是否對應原句仍需人工覆核。完成後格式錯誤最多修正一次，完整性通過與人工翻譯品質分別判斷。這組測試涵蓋問候、稱呼、名字與一般短句，尚不足以評分漫畫慣用語、語氣或複雜跨頁語境，也無法證明網站實際選用的模型名稱。

整頁按閱讀順序翻譯，超過 24 個區域或 6,000 個原文字元時拆批。請求附人名術語與前頁摘要；下一張 OCR 可先執行，翻譯須等待前頁完成。回覆使用時再檢查原文與 ID 指紋。部分批次完成後失敗會保存完成譯文，提交後斷線則保存結果未知，阻止相同輸入自動重送。重新驗證或解除未知鎖定均由可見設定頁操作。

匿名診斷保留於本機，最近 30 個批次的原文、回覆及有限原始協定資料供查核；未知請求鎖另行保存，不隨診斷清單輪替消失。網站協定、可用地區與限額可能改變，Google 仍為預設來源。

候選建置 `2026-10-15T04:35:24.698Z` 在 Chrome 實際閱讀頁完成兩張漫畫、共 16 個區域的匿名翻譯，並將兩張結果套回原頁。偵測／OCR／翻譯分別為 1,792／8,016／4,472 ms，以及 966／4,870／4,287 ms。這些是單次實測，包含初始化與網路等待，不能當成延遲分布。最終套件另補上提交後取消也保存未知鎖的處理，該分支有獨立回歸測試；真實兩頁測試使用前述候選建置。

與先前 Google 譯文比較，Gemini 將一處名字依上下文譯為人名，先前 Google 曾譯成前往某處；另有慣用語變得自然。不過，第二張一處 OCR 錯字仍被 Gemini 當成人名，人物名稱也需術語表固定。16 個區域未見漏框、額外 ID 或整框譯文錯置；這份小樣本檢視尚未完成盲評與正式品質評分。局部補色的警示仍存在，網點上的原文清除需要人工校正。原文、逐框比較、執行紀錄與截圖留在本機。

## WASM 與原生 ONNX

兩者都在本機 CPU 執行。瀏覽器使用 ONNX Runtime Web 1.30.0；原生服務使用 Python 3.14、ONNX Runtime 1.24.1、NumPy 2.4.2 與 Pillow 12.1.1。原生端另有 localhost 圖片傳送、JSON／Base64、解碼及前處理成本。執行庫版本也有差異，速度差不能全歸因於 WASM。

第一階段將兩個代表區域的 float32 輸入保存一次，瀏覽器與原生端讀取相同 bytes，執行完整 encoder／decoder 產生 token。每種執行緒設定先測首次推論，再測三次暖機；模型建立時間獨立記錄。下列結果來自 localhost 隔離 Worker，擴充套件 offscreen 的實際隔離與執行緒仍需另外確認。

| 後端 | 執行緒 | 額外 pthread | 兩區域暖機中位耗時 |
|---|---:|---:|---:|
| WASM | 1 | 0 | 3561.18 ms |
| WASM | 2 | 1 | 1863.97 ms |
| WASM | 4 | 3 | 1759.15 ms |
| 原生 ONNX | 1 | 不適用 | 1382.89 ms |
| 原生 ONNX | 2 | 不適用 | 735.66 ms |
| 原生 ONNX | 4 | 不適用 | 526.91 ms |

所有設定與輪次的 token 完全一致。

第二階段使用同章 17 張圖片、正式偵測／OCR／嵌字及 PNG 編碼。每輪重置頁面文字快取，保留模型下載快取，最多兩張在途。翻譯使用固定 300 ms 回覆與單一請求佇列，零外部翻譯請求。比較 WASM 1、WASM 4 與原生 4 執行緒，各一次冷啟動及三次暖機。

每輪包含 17 張、128 個區域，共 12 輪、204 次頁面處理，全部完成。冷啟動指新建 Worker／推論 session，模型檔已在本機，未計首次網路下載。

| 模式 | 冷啟動整章 | 三次暖機整章 | 暖機中位數 |
|---|---:|---|---:|
| WASM 1 | 243.05 秒 | 245.39／218.63／244.84 秒 | 244.84 秒 |
| WASM 4 | 107.30 秒 | 105.97／105.60／109.22 秒 | 105.97 秒 |
| 原生 OCR 4＋WASM 偵測 1 | 84.76 秒 | 81.06／70.06／72.95 秒 | 72.95 秒 |

四執行緒 WASM 整章中位耗時縮短 **56.7%**；原生 OCR 組再比 WASM 4 短 **31.2%**。每輪在途圖片峰值均為 2、翻譯請求峰值均為 1。Worker 在 WASM 4 實際回報隔離及 SharedArrayBuffer 可用、3 個額外 pthread、有效執行緒 4，持有 3 個模型 session；原生組的瀏覽器只持有偵測 session。

下表以三次暖機的每頁階段計算 P50／P95，單位毫秒。OCR 欄包含該頁辨識流程；階段等待與流水線重疊使各欄不能直接相加成整章時間。

| 階段 P50／P95 | WASM 1 | WASM 4 | 原生 OCR 4＋WASM 偵測 1 |
|---|---:|---:|---:|
| 偵測 | 726／1166 | 353／413 | 709／1104 |
| OCR | 11577／25553 | 4592／10162 | 1917／5012 |
| 固定翻譯 | 2170／4378 | 2193／4429 | 2211／4492 |
| PNG 編碼 | 672／1292 | 888／3173 | 633／2830 |
| 單頁完整流程 | 28570／40484 | 12212／19142 | 8274／14942 |

WASM 1 與 4 的所有輪次、128 個區域辨識文字完全一致。原生組每輪結果亦一致，但有 5 張、14 個區域與瀏覽器組不同；其中含特殊字與低品質頁面，尚無人工真值判定優劣。原生組仍需處理 Canvas／Pillow 前處理差異，速度不足以作為改換預設後端的單一依據。

整段量測的 32,877 筆 50 ms 計時器延遲，P50 為 0 ms、P95 為 13.24 ms、最大 1,375 ms。這是三種模式合併資料；尚不足以證明四執行緒的頁面反應與單執行緒相同，PNG 編碼 P95 也有增加。測試期間保留一般桌面活動，使用者瀏覽與短暫建置工作會造成干擾。

每約 2 秒採樣一次，共 689 筆；採樣從第一組執行途中開始。所有 Chrome 程序的 CPU 核心百分比 P50／P95 為 187%／392%，工作集總和峰值約 6,966 MiB、私有位元組約 6,002 MiB；這包含其他分頁，工作集還可能重複計算共享頁面。原生測試服務程序的工作集峰值約 546 MiB、私有位元組約 918 MiB，其整段 CPU P50／P95 為 0%／617%，其中包含等待瀏覽器組完成的閒置時間。CPU 100% 代表一個邏輯核心的時間；這些數字無法用來宣稱擴充套件自身占用多少 RAM，或各模式已完成公平的 CPU 利用率比較。

完整流程的瀏覽器與原生前處理分別採 Canvas 與 Pillow，辨識差異另列，不能用固定張量的 token 一致替代整頁回歸。記憶體量測須標示範圍：JS heap、WASM 記憶體、Chrome 全程序工作集與私有位元組各有不同涵義。全 Chrome 程序量測包含其他分頁，工作集總和亦可能重複計算共享頁面。

`auto` 在沒有合格本機設定檔時採 1。手動 2／4 需要實際隔離與 pthread，初始化失敗則重新建立單執行緒 Worker。更改設定於下一次釋放／重建後生效。固定張量加速、整章加速及頁面反應分別列證據，人工品質未覆核的結果不當成 OCR 真值。

依據：[ORT 執行緒設定](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)、[Chrome 擴充套件隔離文件](https://developer.chrome.com/docs/extensions/develop/concepts/cross-origin-isolation)。

## 快取、介面與休眠驗收

Chrome 的隔離 UI fixture 使用正式元件與合成快取資料，確認清單篩選、計量、拖曳、浮球、隱藏恢復及 400×720 視窗限制。真實擴充套件快取頁的使用者回報為 30 份文字與校正、100.6 KiB；Chrome origin 用量估算為 450.24 MiB，舊模型有 4 項尚待掃描。未掃描內容列為未知，已計量值 0.0 KiB 不代表模型未占磁碟空間。

實際漫畫工作完成後，使用者讀到「推論狀態：已釋放」，60 秒後重新檢視仍可查看快取。這支持閒置後資源釋放與文字快取保留；沒有以程序 RAM 歸零作為驗收。實際擴充套件在模型載入期間的 pthread 數未取得，隔離測試環境的四執行緒證據另列於上節。

最終程式通過 81 個測試、型別檢查零錯誤與警告；原生 HTTP／OCR 的 4 項檢查通過。完整發布套件核對 manifest、每個建置檔案及 ZIP CRC；GitHub CI 結果另依發布提交確認。實際閱讀頁的可讀取 console 記錄包含網站腳本錯誤與長任務警告，沒有把網站診斷當成擴充套件錯誤；擴充套件管理頁的私人紀錄未由瀏覽器工具讀取。

## 重現

準備合法可使用的本機頁面、固定區域及模型後執行：

```powershell
Set-Location -LiteralPath 'C:\path\to\comic-transcriber'
python scripts/native-threads.py --prepare-only
node scripts/resources-regression.mjs
```

這個服務只託管隔離 UI fixture 與模型測試，不啟動或控制瀏覽器。開啟輸出的 loopback URL，執行 WASM 1／2／4 固定張量量測；結束後以 `python scripts/native-threads.py` 執行原生對照。固定輸入的 SHA-256 保存在本機結果。

完整流程使用測試服務的 `/chapter` 頁面及 `scripts/native-benchmark-service.py`。原生測試服務只接受明確指定的 loopback 測試來源；正式 `backend/server.py` 的來源規則維持獨立。服務與瀏覽器量測各自以前景方式執行，完成後循正常結束操作收尾。

```powershell
python scripts/native-benchmark-service.py --origin http://127.0.0.1:PORT --threads 4
```

測試結果、真實漫畫、譯圖與協定診斷保存在忽略版控的 `artifacts/`。公開範例使用原創示意圖。
