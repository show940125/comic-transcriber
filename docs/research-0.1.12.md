# 0.1.12 驗證紀錄

日期：2026-10-15。範圍為首次翻譯連線錯誤、漫畫專屬指示及發布流程。

## 冷啟動問題

使用者回報首次整章翻譯出現 `Could not establish connection. Receiving end does not exist.`，續翻後初譯與 Gemini 二段校正均可完成。未取得當次 runtime 日誌，因此歷史事件的唯一原因仍無法確認。

程式中的 `offscreen()` 原先以 `hasDocument()` 判斷可用性。兩個工作重疊時，第二個可能在 `createDocument()` 尚未完成，或文件模組尚未註冊訊息接收器時送出工作。最小測試分別控制這兩個時間差，舊程式均回傳相同錯誤。

修正後，建立與接收器就緒握手共用一個 Promise。`offscreen-ready` 僅回報是否就緒，最多等待 10 秒；缺少接收器時只重試此探測。推論、Chrome Translator 與 Gemini 工作在握手後各派送一次，工作提交失敗會回報，保留既有未知結果鎖定規則。

## 漫畫專屬翻譯指示

- 設定「故事上下文」新增 `translationInstructions`，最多 3,000 字；舊設定預設空字串，本機保存。
- Gemini 整章校正、匿名單批翻譯、WebLLM 與本機 LLM 均收到此欄位。明確術語譯名優先，固定 JSON 與區域 ID 核對保留。
- 整章校正同時帶入前頁摘要；校正提示版本為 2，上下文指紋包含摘要與專屬指示。設定變動時不套用舊回覆。
- Google／Chrome 的逐框初譯快取不因指示變動失效；可沿用初譯重跑整章校正。設定目前為全域，沒有作品設定檔自動切換功能。

## 驗證結果與界線

- 113 個測試通過，涵蓋兩種冷啟動競態、探測逾時、提交不重送、指示傳送、舊設定讀取、快取與校正對應。
- 型別檢查 0 錯誤、0 警告。
- 真實隔離 Chromium：設定欄位經儲存與重新載入後內容一致；5 輪初始化／釋放，每輪兩個並發工作首次即成功，且沒有載入模型或呼叫 GPU 探測。
- 初始化回歸後，單次點擊完成原創合成頁的一個指定區域：實際離線 WASM Manga-OCR → 本機翻譯測試端點 → 嵌字 → PNG 匯出。端點收到完整自訂指示；翻譯回覆為 fixture，測試中沒有 Google／Gemini 遠端請求，也沒有 pageerror。
- 完整 17 頁真實漫畫與 Gemini 語意品質本次未重測；先前驗證見 [0.1.11 紀錄](research-0.1.11.md)。

本機證據為 `artifacts/regression-0.1.12/report.json`、設定截圖及原創合成頁結果；測試設定檔已於瀏覽器關閉後清除。重現命令為 `node scripts/cold-start-regression.mjs`，需已建置並 stage OCR 權重，以及本機合成語料 `artifacts/corpus/`。

離線發布包經 CRC、manifest、檔案集合、建置內容與模型雜湊核對。發布目錄保留最新兩版；容量清理方式見 [容量管理](storage.md)。
